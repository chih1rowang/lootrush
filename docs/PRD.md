# 〈项目名待定〉游戏限时贩售与抽卡后端 — 产品需求文档

- 版本：v0.9（草案，待项目名拍板与开放问题澄清后升 v1.0）
- 日期：2026-10-25

## 1. 一句话定位

游戏"限时贩售"运营活动的后端系统：开售洪峰下库存不超发、付了钱道具必到账、钱货每日可对账。

## 2. 用户与角色

- **玩家**（替身网页扮演）：蹲守限时商品开售、抢购、支付、抽卡、看排行榜。
- **运营**（管理后台）：上架商品、设置库存与开售时间、查订单流水、看对账报表。

## 3. 核心业务流（一个玩家的完整夜晚）

登录 → 刷贩售页等开售（倒计时）→ 整点抢购（成功即锁定库存）→ 模拟支付 →
背包到账 → 抽卡十连 → 看排行榜 → 15 分钟不付款：订单关闭、库存回补。

## 4. 功能范围

**v1（按最小循环顺序）**：
全局重命名与账号注册登录 → 商品上架（管理端）→ 抢购主线（Lua 原子扣减＋快速失败）→
支付与幂等（假支付公司＋回调）→ 异步发奖与事务 → 延迟关单与库存回补 →
对账 → 抽卡（概率＋保底＋审计流水）→ 排行榜 → 压测与调参报告。

**后续可选**：软保底、UP 池、随机个人货架、主动取消订单。

**明确不做**：真实支付、战斗/战力系统、跨服玩法、手机端适配。

## 5. 开发铁律

**最小循环**：每循环只交付一小块可独立验收的功能，节奏固定为
"说清任务 → AI 写码 → 跑通验收 → 人看懂关键代码 → git 存档"。

## 6. 非功能需求

- 单机 JMeter 压测目标：**10000 并发**（抢购接口为主）；
- 任何情况下超卖为 0、重复发货为 0；
- 每个关键动作：页面上可见、后台表里可查（三连验收标准）；
- 全链路可观测：日志（含请求追踪号）、Zipkin 行程单、Grafana 曲线。

## 7. 视觉与交互规范（替身网页）

- 游戏官网风：深色主题、背景大图＋半透明遮罩淡化、发光与渐变点缀、大字倒计时；
- 素材仅用免费可商用图库（Unsplash 等），**不使用任何游戏公司官方素材**；
- 形态轻量：Vue3 以 CDN 方式引入，不搭前端工程化构建，保持后端项目本色。
