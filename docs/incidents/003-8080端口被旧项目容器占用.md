# 事故报告 №003：程序启动报 8080 端口被占用

- 日期：2026-10-25
- 严重程度：低
- 状态：已修复

## 1. 现象

IDEA 点运行，Spring 大 logo 正常打印，最后一步报
`Web server failed to start. Port 8080 was already in use`，退出码 1。

## 2. 复现步骤

在 gateflow-conductor 容器运行期间启动本项目即可复现。

## 3. 排查过程

`netstat -ano` 查 8080 的占用 PID（33940），`tasklist` 认出是
`com.docker.backend.exe` —— 占用者是某个 Docker 容器而非普通程序；
再用 `docker ps` 按端口过滤，锁定 `gateflow-conductor`
（映射 `127.0.0.1:8080->8080`，旧项目遗留容器，已运行 20 小时）。

## 4. 根因

旧项目 gateflow 的工作流引擎容器长期占用宿主机 8080，与本项目的服务端口撞车。
本项目端口规划时检查了 3306/3307 的占用，漏查了 8080。

## 5. 修复

`docker stop gateflow-conductor`（停用而非删除，容器与数据完好，
需要时 `docker start gateflow-conductor` 一键复活）。8080 释放后项目正常启动。

## 6. 预防

- 端口登记表（README）补齐所有新旧项目的端口占用，起服务前先 `netstat` 查一遍；
- 旧项目不用时及时 `docker stop`，不给新项目埋雷；
- 注：conductor 本就在 gateflow 改造方案的"砍掉"名单上（改用自研轻量状态机），
  长期看它不会回来。
