# 事故报告 №001：中间件首次部署的两起端口冲突

- 日期：2026-10-25
- 严重程度：中（部署被阻塞约 10 分钟，无数据损失）
- 状态：已修复

## 1. 现象

1. `docker compose up -d` 时，MySQL 容器启动失败，报错
   `Bind for 0.0.0.0:3306 failed: port is already allocated`（3306 门牌被占）。
2. MySQL 修好后，RocketMQ 控制台访问 http://localhost:8180 始终无响应（curl 返回 000）。

## 2. 复现步骤

- 现象1：在已有容器映射 3306 的机器上执行 `docker compose up -d`（本机即如此，无需刻意构造）。
- 现象2：查看容器日志 `docker logs mall-mq-dashboard`，可见
  `Tomcat started on port 8082` —— 程序实际监听 8082，而我们的端口映射写的是 8180→8080。

## 3. 排查过程

- 现象1：先 `netstat -ano | findstr 3306` 找到占用进程 PID，`tasklist` 查出是
  `com.docker.backend.exe` —— 说明占用者是**另一个 Docker 容器**而非本机软件。
  再用 `docker ps -a` 按端口过滤，找到两个老容器：
  `student-course-mysql`（占 3306）和 `gateflow-mysql`（占 3307）。
- 现象2：容器状态是 Up 但端口无响应，说明程序没死、只是"门牌不通"；
  `docker logs mall-mq-dashboard` 直接看到 Tomcat 启动在 8082，定位到映射写错。

## 4. 根因

1. 本机存在历史项目的 MySQL 容器，占用了默认的 3306 和备用的 3307；
   部署前没有先检查端口占用情况。
2. `apacherocketmq/rocketmq-dashboard` 新版镜像的默认端口从 8080 改成了 8082，
   配置是按旧资料写的，没有以实际日志为准。

## 5. 修复

- MySQL 映射改为 `3308:3306`，同步改 `application.yml` 的连接地址为 `localhost:3308`；
- 控制台映射改为 `8180:8082`，重建容器后 http://localhost:8180 返回 200。
- 未动两个老容器（后续做 gateflow 改造还要用）。

## 6. 预防

- 以后每接手一个端口，先跑 `netstat -ano | findstr <端口号>` 确认无人占用再写配置；
- 对第三方镜像，启动后先看 `docker logs` 里实际监听的端口，再确定对外映射；
- README 维护"本项目端口登记表"，新旧项目端口一律登记在册，避免互相踩踏。
