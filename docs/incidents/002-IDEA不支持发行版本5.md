# 事故报告 №002：IDEA 报"错误: 不支持发行版本 5"

- 日期：2026-10-25
- 严重程度：低（配置错位，项目本身无问题，5 分钟修复）
- 状态：已修复

## 1. 现象

IDEA 里点绿色三角运行项目，报 `java: 错误: 不支持发行版本 5`，程序没起来。

## 2. 复现步骤

IDEA 打开项目后，在右下角 Maven 进度条还没跑完（或从未点过 Maven 刷新）时
直接点运行，即可复现。

## 3. 排查过程

1. 先确认项目本身没问题：命令行 `./mvnw compile` 早已编译通过 → 问题不在代码和 pom，
   在 IDEA 自己的配置层。
2. 查项目里的 `.idea/misc.xml`：项目级 SDK 指向 temurin-21、语言级别 JDK_21，都正常。
3. 查 IDEA 全局 JDK 登记表（`AppData/Roaming/JetBrains/IdeaIC2025.1/options/jdk.table.xml`）：
   机器上共存三个 JDK（8 / 17 / 21，其中 21 在 D:\jdk\temurin-21），全部真实有效，
   SDK 无效的假设排除。
4. 剩下唯一嫌疑人：模块级（Module）的"语言级别 / 编译目标"——IDEA 对每个模块单独
   存一份这个设置，默认值是 Java 5；它本该在 Maven 导入完成时被自动改成 pom 里写的 17，
   但导入没完成，默认值 5 留在原地。新版 JDK 早就拒绝编译 Java 5 标准的代码，于是报错。

## 4. 根因

IDEA 的编译配置分两层：项目级和模块级。模块级默认是古老的 Java 5，
需要 Maven 导入动作来覆盖成 pom 声明的版本；本项目打开后导入未完成即触发编译，
默认值没来得及被替换。机器上多 JDK 并存（8/17/21）让排查时更容易怀疑错方向。

## 5. 修复

1. Maven 工具窗口 → Reload All Maven Projects（刷新图标），等待完成——
   模块语言级别自动变为 17，这是治本的一步；
2. 如仍报错：File → Project Structure → Project 的 Language level 选 "SDK default"，
   Modules 里 flash-mall 同样；再查 Settings → Build → Compiler → Java Compiler，
   把 Project bytecode version 和 flash-mall 的目标版本都设为 17。

## 6. 预防

- 打开任何新项目，先等右下角 Maven/索引进度条彻底跑完再点运行；
- 见到"不支持发行版本 X"类报错，第一反应去查语言级别和编译目标两层配置，
  不要怀疑代码、更不要急着重装 JDK。
