# 导览 012：循环 9C —— 敏感字段透明加解密插件（简历行本体）

> 讲法同前：比喻搭脚手架，紧跟规范表述。

## 业务前提：为什么这个功能本来就该有

游戏是中国**实名制强制最严的领域**（国家新闻出版署规定游戏必须实名认证＋防沉迷）。
身份证号属于《个人信息保护法》定义的**敏感个人信息**，落库不加密就是合规欠账。
所以本循环不是"为了插件而插件"——是给 LootRush 补上实名认证功能，
而实名信息的存储安全由插件来兜。

## 这一循环做了什么

玩家可提交实名认证（姓名＋身份证号）；**落库自动加密、查询自动解密、对外脱敏**：
- 库里（DBeaver 裸查）：`enc:v1:xJ8fK2...` 密文；
- 业务代码里：拿到的永远是明文（`310110199001011230`）；
- 接口出参：`310******1230`（脱敏遮罩）。
业务 Mapper **零改动**——字段上打一个注解，其余全部由插件完成。

## 追问弹药库（每层都有实证答案）

| 追问 | 答案要点 |
|---|---|
| 为什么用插件不用 TypeHandler？ | TypeHandler 要逐字段逐 Mapper 声明（侵入、易漏）；插件反射扫 `@EncryptedField` 注解全局生效，Mapper 零侵入 |
| 为什么拦 Executor 不拦 StatementHandler？ | Executor 层参数与返回值是**业务对象**，反射处理字段最自然；StatementHandler 层只剩 SQL 字符串（这与 9B 恰好互补：两个插件各守一层） |
| 为什么 AES 不像密码那样用哈希？ | 密码永远不需要读回来→单向 BCrypt；身份证需要展示→可逆 AES。**"可不可逆"由业务决定** |
| 为什么用 GCM＋随机 IV？ | 同一明文每次密文不同（防频率分析）；GCM 自带完整性校验（篡改即解密失败）。代价：无法等值检索——业务不需要模糊查实名信息；要等值检索需 HMAC 确定性索引列（代价能讲清） |
| `enc:v1:` 前缀干什么？ | 三重用途：解密只认自家密文（其他原样返回）、防重复加密/解密（守卫已测试）、未来换算法可灰度升级 v2 |
| 密钥放哪？ | 配置注入（32 字节）；生产应上 KMS/配置中心——边界诚实声明 |
| 加密后无法 LIKE 怎么办？ | 同"等值检索"条；实名信息无模糊查需求 |

## 测试怎么证明"库真的是密文"

关键一招：测试里用 **JdbcTemplate 裸查**（绕开 MyBatis 插件）直接看存储层——
断言 `id_card` 以 `enc:v1:` 开头且不含明文；再走 Mapper 读回断言拿到明文。
四条测试：落库密文＋读回明文／读两次不二次解密（前缀守卫）／校验位非法拒绝／脱敏格式。

**附带产出：身份证校验位算法**（GB 11643-1999）——加权求和 mod 11 映射校验码。
被问"你校验了什么"时，答得出"正则＋校验位"比只答"正则"高一档。

## 亲眼看（程序重启后）

```bash
# 1. 登录拿手环（player1）
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d '{"username":"player1","password":"pass123"}' | grep -oE '"token":"[^"]+"' | cut -d'"' -f4)

# 2. 提交实名（JSON写文件避开编码坑）
printf '{"realName":"ZhangSan","idCard":"310110199001011230"}' > /tmp/rn.json
curl -s -X POST http://localhost:8080/api/me/realname -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d @/tmp/rn.json

# 3. 看脱敏视图
curl -s http://localhost:8080/api/me -H "Authorization: Bearer $TOKEN"
```

三步预期：第 2 步返回 code 0；第 3 步 `idCardMasked` = `310******1230`。
杀手锏在 DBeaver：`SELECT id_card FROM user WHERE username='player1'` →
**看到的是 enc:v1: 开头的密文**——"库里没有明文"由你亲眼盖章。
