# 导览 014：循环 9D —— 抽卡商业化调优（160 钻、两级商城、金装每周轮换）

> 讲法同前：比喻搭脚手架，紧跟规范表述。本循环是"产品需求驱动后端改造"的小样本。

## 三个产品需求与对应实现

### 1. 抽卡单价 100 → 160 钻（十连 1600）

真实手游的行业惯例价（160/抽）。改动只有常量 `PRICE_PER_PULL`，但连锁影响全被
测试网住：十连账目断言、千抽审计余额、排行榜计分断言全部同步更新——**改动一个
常量，42 条测试告诉我们该改哪几处**，这正是自动化测试的价值现场。

### 2. 商城稀有度分两级（蓝/紫），金色只属于卡池

- 上架接口新增 rarity 字段，校验只允许 1（蓝）/2（紫）；**传 3 直接被拒**
  （"最高级只能从卡池获得"写进了校验消息）；
- 种了 6 件有名字的正经道具：见习短剑/星纹护符/疾风之靴（蓝）、
  苍穹之翼碎片/龙鳞胸甲/幻月法环（紫），全部长期在售；
- 货架接口透传 rarity（前端商品卡按稀有度上色用）。

### 3. 金装 10 件，5 件一期每周轮换

**产品规则**：金色（rarity 3）只能抽卡获得；金装池 10 件，每期上场 5 件，
每 7 天轮换一期；卡池页要能展示"本期阵容、本期起止时间、下期阵容"。

**实现（惰性轮换，零定时任务）**：
- 新表 `gacha_gold_item`：10 件金装按 slot_order 排队的"出场顺序表"；
- 新表 `gacha_rotation_state`：单行存"轮换纪元起点"（anchor）；
- **当前是第几期 = 距纪元起点的整周数 % 组数**——纯计算推导，不依赖任何定时器；
  服务重启、跨天、跨周都自然正确（和商品四态"推导不落库"同一思想）；
- 抽卡出金时从**本期阵容**随机出一件；公示接口返回本期/下期阵容与起止时间
  （前端直接用）。
- 管理端可调 anchor（比如把纪元起点改到现在=立即开启新一期），演示轮换切换。

**概率结构（公示数据）**：蓝 89%、紫 10%、金色合计 1%（本期 5 件各 0.20%）。

## 一次轮换的时间线（举例）

```
第1期(10-26~11-01)：逐星者之刃/月蚀长弓/焚天法杖/破晓之枪/极夜双刃
第2期(11-02~11-08)：苍雷战锤/绯樱折扇/玄冰短匕/曜日重剑/幽萤魔典
第3期(11-09~)：回到第1期阵容……无限循环
```

## 本循环踩到的小坑

测试里两处内部类引用忘了写外层限定名（`GoldLineup` → `GachaService.GoldLineup`），
编译器逐个抓出——改内部 record 后全项目搜索旧引用应是肌肉记忆。
另：排行榜测试的计分断言（1000）也随单价同步成 1600——**改一个常量，测试网会
告诉你所有受影响的地方**（本循环第二次体会，这就是坚持写测试的复利）。
