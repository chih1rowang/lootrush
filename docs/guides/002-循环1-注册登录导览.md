# 导览 002：循环 1 —— 注册登录是怎么工作的

> 按第一规则写的文档：先人话，再代码。

## 这一循环做了什么

玩家现在可以：注册一个账号（送 1000 钻石）→ 登录拿一张"通行证"（JWT）→
带着通行证访问需要登录的接口（目前只有 /api/me，以后背包、订单都靠它）。

## 三个关键角色（每个都是面试考点）

**1. BCrypt（存密码的方式）**
密码绝不能明文存库。BCrypt 做两件事：每次加密前撒一把**随机盐**（同一密码
两次加密结果都不同），再把哈希过程**故意放慢**（暴力试密码的人也得跟着慢）。
数据库被拖走，攻击者也无法反推出你的明文密码——这是它比 MD5 强的本质原因。
验证时不"解密"（哈希不可逆），而是用同样的方式算一遍比对。

**2. JWT（通行证）**
三段式字符串：头部(用什么算法).载荷(你是谁、何时过期).签名(防篡改)。
关键性质：服务端**不存它**（无状态）——验签只靠只有服务器知道的密钥；
代价是签发后无法提前作废，只能等过期。这是面试必问的取舍题。

**3. 拦截器（检查岗）**
所有 /api/** 的请求先过 JwtInterceptor 验通行证，通过后把 userId 塞给业务代码；
/api/auth/**（注册登录）和未来的支付回调在白名单里免检。

## 一次登录请求的完整旅程

浏览器 POST /api/auth/login {username, password}
→ 拦截器放行（白名单）
→ AuthController 校验参数格式（6-32位等）
→ AuthService 查库取哈希 → BCrypt 比对
→ 通过：JwtUtil 签发通行证返回；不通过：抛 BizException(401)
→ 全局异常处理器把异常翻译成 {"code":401,"msg":"用户名或密码错误"}

## 亲眼看（自己动手验收）

程序跑起来后，Git Bash 里依次：

```bash
# 1. 注册（应返回 userId 和 1000 钻石）
curl -X POST http://localhost:8080/api/auth/register -H "Content-Type: application/json" -d '{"username":"player1","password":"pass123"}'

# 2. 登录（应返回一长串 token，复制下来）
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d '{"username":"player1","password":"pass123"}'

# 3. 带通行证查自己（把 <token> 换成上一步拿到的）
curl http://localhost:8080/api/me -H "Authorization: Bearer <token>"

# 4. 不带通行证硬闯（应返回 code 401 未登录）
curl http://localhost:8080/api/me
```

再开两个窗口对照看：
- DBeaver 连 localhost:3308 → lootrush 库 → user 表：能看到 player1 那行，
  password_hash 是一串 `$2a$10$...` 开头的乱码（BCrypt 的长相）；
- http://localhost:9411 Zipkin：服务名已是 **lootrush**，每次请求一张行程单。

## 本循环踩到的小坑（Boot 4 迁移点）

Jackson（把对象转成 JSON 文本的库）在 Boot 4 升级到 3.x，Java 包名从
com.fasterxml.jackson 搬到了 tools.jackson——import 写老包名会编译报错。
症状一眼可辨（"程序包 com.fasterxml.jackson.databind 不存在"），改 import 即可。
