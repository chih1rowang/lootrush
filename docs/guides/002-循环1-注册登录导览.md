# 导览 002：循环 1 —— 注册登录是怎么工作的（新手版）

> 按第一规则写的文档：全部用生活比喻讲，术语都配人话。

## 这一循环做了什么

你现在有了一个能注册账号的小系统：**注册就送 1000 钻石；登录成功发你一条"电子手环"；以后干任何需要身份的事（看背包、下单、抽卡），都要戴着这条手环来。**

## 三个关键角色（每个都是面试考点）

### 1. 密码是怎么存的：搅碎机（BCrypt）

你的密码进数据库**之前**，会先被一台"搅碎机"搅成一团乱码，而且**永远无法搅回去**。
比如密码 `pass123`，库里存的是：`$2a$10$Xk4f...`（60 个随机字符）。

这台搅碎机有两个讲究：

- **每次搅之前撒一把随机作料**（行话叫"盐"）：同一个密码，今天搅和明天搅，结果都不一样。这样就算坏人偷走整个数据库，也没法拿一张"常用密码对照表"挨个对答案——因为每个人的作料都不同。
- **它故意搅得很慢**（每次零点几秒）：你登录时慢这一点点完全无感；坏人想暴力试一亿个密码，就得跟着慢一亿次。

面试考点：为什么不用老掉牙的 MD5？——MD5 搅得太快、而且同一个密码永远搅出同一团乱码，坏人用预先算好的对照表秒破。

登录验证不是"把乱码还原成密码再比对"（还原不可能！），而是：**把你这次输的密码同样搅一遍，看能不能和库里那团对上**——机器自己会带着当年的作料比对。

### 2. 登录发给你什么：电子手环（JWT）

登录成功，服务器发你一长串字符，长这样：`eyJhbGciOiJIUzI1NiJ9.eyJzdWIi...`——这就是 JWT，一张电子手环。它分三截（用点隔开）：

```
用啥方法防伪(头部) . 你是谁+几点过期(内容) . 防伪签名
```

它最妙的一点：**服务器根本不用记自己发过哪些手环**。你下次戴着来，服务器掏出只有它自己知道的秘密配方一验，就知道这手环是真发的还是你自己在纸上画的。行话叫"无状态"——省了存手环的柜子，也省了每次去柜子里翻。

代价（面试爱问的取舍）：手环一旦发出去，**没法提前作废**，只能等它到点失效。我们设的是 12 小时。所以"退出登录"在这个方案里只是前端把手环删了，服务端不care——想真正踢人下线就得引入黑名单，那是后话。

### 3. 门口保安（拦截器）

我们给所有 `/api/` 开头的网址配了个保安，规矩：

- **注册、登录这两个门免检**（不然就成了"先有手环才能办手环"的死循环）；
- **其他门一律先伸手环**：验过的放行，并告诉屋里的同事"这位是 userId=X 的客人"；没带的、假造的，直接回一句"未登录"，根本进不到业务那层；
- 以后"支付回调"那个门也会免检——那是快递员敲门，用的是另一套暗号（签名），不是玩家手环。

## 一次"登录"的完整旅程（全程人话）

1. 你（命令行或网页）敲响登录的门，递上用户名和密码；
2. 保安看一眼：登录在免检名单，放行；
3. **前台接待**（AuthController）：先检查你表格填得规范吗（用户名 3-20 位、密码 6-32 位），不规范直接打回并说明原因；
4. 转交**办事员**（AuthService）：去档案室（数据库的 user 表）按用户名找到你那一行，取出当年存的那团乱码；
5. 办事员把你这次输的密码放进搅碎机搅一遍和它比对——
   - 对上了：找**发卡处**（JwtUtil）给你打一条 12 小时的手环，返回；
   - 对不上：喊"用户名或密码错误"（注意：**查无此人和密码错误是同一句话**，免得坏人靠报错试探出哪些用户名存在）；
6. 不管结果如何，回给你的永远是同一种信封格式：`{"code":0,...}` 成功、`{"code":401,...}` 失败。负责把各种意外翻译成统一信封的是**翻译官**（全局异常处理器），它还有条铁律：系统内部出大错时，对客人只说"服务器开小差了"，技术细节全部写进日志，一个字不外泄。

## 文件地图（哪个文件扮演哪个角色）

| 文件 | 它是谁 |

| user/AuthService.java | 办事员：注册时搅密码，登录时对密码 |
| user/JwtUtil.java | 发卡处：造手环、验手环 |
| config/JwtInterceptor.java | 门口保安 |
| config/WebConfig.java | 保安的岗位手册（哪些门免检） |
| user/AuthController.java | 前台接待 |
| common/ApiResponse.java | 统一的信封格式 |
| common/GlobalExceptionHandler.java | 翻译官 |
| user/UserMapper.java | 档案室取放员（真正会写 SQL 的） |
| docs/sql/schema.sql | 档案柜的图纸 |
| test/.../AuthServiceTest.java | 体检表（`./mvnw test` 一键重新体检） |

小知识：user 表上的"唯一索引"（uk_username）就是档案室的登记规矩——**同一个名字只许立一份档**，第二份想插进去会被数据库本身直接拒绝，连代码都不用写判断。这是"让数据库帮你守规矩"的典型思路。

## 亲眼看（四条命令 + 两个窗口）

先解释 curl：它是命令行里"假装成浏览器去敲接口"的小工具。命令里几个零件：
- `-X POST`：这次是"交表格"，不是"路过看看"；
- `-H "Content-Type: application/json"`：随表格附一句"我交的是 JSON 格式"（JSON＝全世界通用的填表格式，就是大括号加引号那种）；
- `-d '...'`：表格内容本身。

```bash
# 1. 注册（应收到 userId 和 1000 钻石）
curl -X POST http://localhost:8080/api/auth/register -H "Content-Type: application/json" -d '{"username":"player1","password":"pass123"}'

# 2. 登录（应收到一长串 token——你的手环，复制下来）
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d '{"username":"player1","password":"pass123"}'

# 3. 戴着手环查自己（把 <token> 换成第2步那串）
curl http://localhost:8080/api/me -H "Authorization: Bearer <token>"

# 4. 不戴手环硬闯（应被回 "code":401 未登录）
curl http://localhost:8080/api/me
```

两个对照窗口：

- **DBeaver**（数据库的图形界面，像一张张 Excel）：连 localhost:3308 → lootrush 库 → user 表 → 点 Data 标签：能看到 player1 那行，password_hash 列是 `$2a$10$` 开头的乱码（搅碎机的作品），diamond 列是 1000；
- **Zipkin**（http://localhost:9411，行程单档案室）：服务名已是 **lootrush**；你刚才每敲一次接口，这里就多一张行程单，点开能看到这次请求在"保安→前台→办事员"各站花了多少毫秒。

## 本循环踩到的小坑（人话版）

Spring Boot 4 自带的"格式转换器"（把程序里的对象变成 JSON 文本的那台机器，名叫 Jackson）升到了第 3 代，把自家**门牌号**从 `com.fasterxml.jackson` 搬到了 `tools.jackson`。代码里按老门牌去找它，就报"程序包不存在"。
教训入库：以后再看到"程序包 xxx 不存在"，第一反应不是"我代码写错了"，而是"**是不是什么库换代搬家了**"。
